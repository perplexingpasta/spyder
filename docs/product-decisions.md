# Product decisions

Settled product-behavior decisions, with the reasoning, so they don't have to be re-asked. Architectural decisions live in `docs/adr/`.

**Decided by:** **User** means the user chose it explicitly (2026-11-21 grilling session). **Claude** means a default Claude picked to fill a gap the user didn't address; the user may revisit these.

**Rule for implementing agents:** treat everything here as settled. Ask the user only about behavior that is **not** covered here or in `SPYDER_PLAN.md`. If you think a decision should change, ask. Don't silently deviate.

| # | Decision | By | Why | Rejected alternatives |
|---|---|---|---|---|
| P1 | Spyder is personal, Windows-only and has no AI (ADR-0009). | User | Personal accountability tool on the user's own machine. | Cross-platform, AI categorization or summaries |
| P2 | **Always-on sessions:** during work hours every minute belongs to a session. If none is running, an **open session** starts on its own. | User | Untracked time is where accountability leaks. With always-on, every gap has to be explained. | Manual start only; manual plus a gap nudge |
| P3 | Four session kinds: **Planned** (name + duration + direction), **Timed** (duration only, labelled at the end), **Open** (count-up, labelled at the end or at check-ins), **Break**. | User (refined by Claude) | These are the user's three ways to track a session, plus breaks so rest time is honest instead of hidden. | — |
| P4 | Planned sessions let the user choose **count up (0→30) or count down (30→0)**. The default is set in Settings (initially *down*) and can be toggled per session. | User; default by Claude | The user asked for both directions. Counting down is the usual timer behavior. | — |
| P5 | When a planned or timed session's time is up: **ring plus a prompt**. If ignored, it goes into **overtime** (shown in red, keeps counting) and the prompt **re-nags every 5 min**. Overtime is stored. | User | Overruns stay visible and measurable for planned-vs-actual. Auto-stopping would hide estimation errors. | Auto-stop; ring once and continue silently |
| P6 | **Away time** (idle ≥ threshold, sleep, lock, or app not running) is cut out of the running session. On return, the user classifies it: **Break / Meeting-call / Offline work (with label) / Not working / I was working**. | User | Accounts for missing time honestly. "I was working" exists because reading or watching without input still looks idle. | Automatically mark as break; prompt only for long gaps |
| P7 | Idle threshold: **5 minutes** without keyboard or mouse input. | User | Catches real absences without nagging during short reads. | 3 min, 10 min |
| P8 | **Check-ins every 30 min** on open sessions ("What have you been doing?"; or one click on "Still on X?" once labelled). Answers: log & continue, or log & start fresh. Interval configurable. | User | Labels stay honest while you still remember. The user chose 30 over the recommended 60. | 60 min; no check-ins |
| P9 | Sessions are labelled with a **free-text name** (autocompleted from history) plus an **optional project** from the user's list. | User | Names stay flexible, and projects allow grouping in reports. | Free text only; fixed list only |
| P10 | **Work hours** are set per weekday (with days off) and can be overridden for today only. **Outside hours:** no auto-sessions or prompts, but app/site usage is still logged and shown separately. Default: Mon–Fri 10:00–17:00, weekends off. | User | Matches the user's "10am to 5pm" example. Off-hours data is still useful but shouldn't nag. | One range for every day; no tracking outside hours |
| P11 | **Workday %** = how much of today's scheduled hours has elapsed, clamped to 0–100. Shown in the widget. | User (Rize behavior) | The user explicitly asked for it. A sense of time passing drives urgency. | — |
| P12 | **Categories:** Productive / Neutral / Distracting / Uncategorized, from a default rule list plus user overrides. New apps/sites are Uncategorized until tagged with one click. Rule edits apply retroactively (ADR-0005). | User | No AI (P1). Defaults mean it's useful on day one. | Manual-only tagging; per-session allow lists |
| P13 | **Distraction nudge:** during a work session, **5 continuous minutes** on Distracting apps/sites turns the widget red and shows a toast. It repeats every 5 min while you stay distracted, and each nudge is flagged in the report. **No blocking.** | User (changed from "report only" to a 5-min nudge) | A gentle real-time push without blocking things that are sometimes legitimate (e.g. a YouTube tutorial). | Blocking overlay; report only |
| P14 | The nudge counter resets only after **60 s continuous** away from Distracting things. | Claude | Without this, briefly switching tabs would reset the counter and defeat the nudge ("deception-free"). | Reset on any switch |
| P15 | **Browsers:** Chrome sites come from its address bar. Firefox sites come from window titles. No extensions (ADR-0007). | User | The user uses Chrome and Firefox and declined the extension route. | One extension for both; a Firefox extension |
| P16 | **No break reminders.** Breaks are recorded when you start one or classify away time. | User | The user doesn't want them. | Reminder after 90 min; Pomodoro |
| P17 | **Pause** = the current session stops and a **Break** session runs. **Resume** ends the break and continues the paused session (a countdown continues where it left off). | Claude | In the always-on model paused time must belong to something, and "break" is the honest bucket. Segments make resuming exact (ADR-0004). | Pause that hides the time; no pause |
| P18 | Away time doesn't apply during a **Break**. Being idle on a break is expected, so the break just continues. | Claude | Otherwise every break over 5 min would trigger a pointless "you were away" prompt. | — |
| P19 | After an away period, the **interrupted session resumes** (from the moment you return). If nothing was interrupted, a new open session starts. | Claude | Continuity: you usually come back to the same task. Use *Switch* if not. | Always start a fresh open session |
| P20 | **End of work hours:** the running session is cut at the end time, the day's **review** opens, and the widget shows *Off hours* with a **Keep working (+30 min)** button. That button extends today's hours and can be pressed repeatedly. | Claude | The day needs a clear close for the review. Extra work is an explicit choice, not silent drift. | Keep sessions running indefinitely; a prompt at the end |
| P21 | **No unlabelled time escapes:** starting a new session, pressing Done, or completing the review first asks for a label for any unlabelled session. The review can mark a session "Unknown" instead. | Claude | That's the whole point of the app. "Unknown" is the honest escape hatch. | Allow unlabelled sessions |
| P22 | **Prompts:** one is visible at a time, the rest queue. Priority: away/recovery > timer-end/label/break-end > check-in. Prompts **never auto-dismiss**, and time keeps running while one is open. | Claude | Stacked popups are hostile, and auto-dismissing would let time go unaccounted. | — |
| P23 | **Widget** looks and behaves like Rize's desktop widget (the user said "exactly like Rize"). It's always on top, draggable, remembers its position, can be dismissed to the tray, and comes back via the tray or a hotkey (`Ctrl+Alt+S`). **No Rize logo or brand marks.** The design is based on real Rize screenshots gathered in Phase 0. | User; branding rule by Claude | The user wants Rize's UX. Copying the brand marks themselves isn't appropriate. | Compact pill of our own design; tray only |
| P24 | **Accountability features:** a daily productive-time goal (default 5h), streaks, planned vs actual, an **end-of-day review** with **"Today's wins"** and **"How I'll improve"** sections, and user-defined numeric **KPIs**. | User (wins/improve/KPIs were the user's own addition) | Reflection plus measurable targets. KPIs let the user track outcomes, not just time. | — |
| P25 | **Productive time** = time in work sessions (excluding breaks and away) + away time classified as Meeting or Offline work − time on Distracting apps/sites during work sessions. **Day score** = productive time ÷ scheduled time. | Claude | The numbers can't be gamed by a session name alone: time on YouTube during a session labelled "emails" doesn't count. | Session time only (gameable) |
| P26 | **App/site %** = that app's foreground time ÷ total foreground time in the selected scope. The default scope is *work hours* of the day, with a toggle for *all day*. Example: `youtube.com 38m · 1.2%`. | Claude | Matches the user's example and answers "what share of my working time went where". | — |
| P27 | **Streak** = consecutive scheduled workdays where the goal was met. Days off don't break it. Today counts once the goal is met. | Claude | The standard streak meaning. Weekends off shouldn't reset it. | — |
| P28 | **Export:** one `.xlsx` (with Sessions, Segments, Activity, App-Site summary, Daily summary, Away, Reviews and KPIs sheets) plus the same data as CSVs, for any date range. | User | Opens neatly in any spreadsheet app. | CSV only |
| P29 | Spyder **starts with Windows** by default (can be turned off). | Claude | An always-on accountability tool is useless if you forget to launch it. | Manual launch |
| P30 | Days are local calendar days. Intervals crossing midnight are split at local midnight in reports. | Claude | Matches how people think about "today". | — |
| P31 | **Two widget styles, switchable any time:** *Full* (320×64 pill with title, timer, workday bar, productive/goal and workday ring) and *Compact* (Rize-sized ~176×40 pill with timer + two-line caps caption + workday ring; title, workday % and productive/goal show in a hover card). Setting `widgetStyle` (`"full"` \| `"compact"`, default `"full"`), switchable from Settings and from the expanded widget; applies live. | User (2026-11-21, Phase 0 design review) | The user wants both and the freedom to change their mind. | Only one fixed style |
| P32 | **Starting work outside today's hours extends the day, never shrinks it.** A START or KEEP_WORKING in off hours sets today's override to `start = min(scheduled start, now)`, `end = max(scheduled end, requested end)` (capped at 24:00). On a day off the override is `[now, requested end]`. | Claude (Phase 2) | E8's formula alone would set a 08:30 end when starting at 08:00, cutting the real workday short. | Replace the end only |
| P33 | **An away period that runs past the end of the day it started in** (e.g. sleep from 16:30 to the next morning) closes the interrupted session at the away start, records the away time only up to that day's end, and opens that day's review. If the return is inside new work hours, a fresh open session starts. It doesn't resume yesterday's session. | Claude (Phase 2) | Resuming a session across days would merge two days' work into one session and skip the review. | Resume the interrupted session the next day |
| P34 | **Naming a timed session after its time is up ends it** and starts an open session (scenario 3). Before the time is up, labelling only renames it. | Claude (Phase 2) | A timed session is "named when the time is up" (P3); naming it is the completion step. | Keep it running in overtime after labelling |
| P35 | **Firefox: a page title ending in "YouTube" maps to youtube.com**, in addition to the plan's `- YouTube` suffix. The YouTube home page's title is just `YouTube` (or `(2) YouTube` with notifications), which the plan's patterns missed. | Claude (Phase 4) | The capture check opens youtube.com, and the home page is where most browsing starts. | Leave the home page as an unknown Firefox page |
| P36 | **An apps & sites row that mixes categories** (e.g. youtube.com with one video matched as productive by a title rule) shows the category with the most time. Its time still counts per underlying row in the category totals and the distracting total. The chip creates a rule for the row's key: a domain rule for a site, an app rule for an app, a title rule for an unmatched Firefox page. Private browsing can't be re-categorized. | Claude (Phase 5) | One chip per row keeps the table readable. The totals stay exact. | One row per (key, category) |
| P37 | **Review leftovers** = finished, unlabelled, non-break sessions plus away periods without a classification, on the reviewed day. The session still running isn't a leftover. Completing a review again later updates its snapshot. Pending away periods from an earlier day (whose prompt is gone) are classified directly from the Review page, with the same effects as the prompt. | Claude (Phase 5) | The running session can't be named "for the day" yet. Re-completing lets late edits reach the snapshot. | Block re-completion |
| P38 | **Week bar stacks** split each day's work time by the category of the activity it overlaps (productive / neutral / uncategorized / distracting), then add break and away (not working + pending). Work time with no activity (meetings, offline work, gaps) is shown as productive, matching P25. A bar's total = work + break + away. | Claude (Phase 6) | Keeps the bars consistent with the Productive stat and the day totals. | Stack the activity category totals directly (double-counts activity during breaks) |
| P39 | **Title patterns apply at read time.** Reports re-run the patterns over stored Firefox rows that have no domain, so a pattern added later re-labels past activity. Stored rows aren't rewritten. Default rules and default title patterns are read-only. Changing a default rule's category creates a user rule, and deleting that user rule brings the default back. | Claude (Phase 6) | Same approach as categorization (ADR-0005); no migrations of activity data. | Rewrite activity rows on save |
| P40 | **Settings are validated in main** (`cleanSettings`): unknown keys are dropped, enum values checked, numbers rounded and raised to a minimum (e.g. idle and check-in ≥ 1 min). Switching today off ends the workday at once, which opens the review like 17:00 does. `autostart` is only stored until Phase 8. | Claude (Phase 6) | Bad values can't break the engine. | Validate only in the UI |
| P41 | **Export details.** The range is chosen in a dialog (Today, This week, This month, Last 30 days, Custom), reachable from Settings and the Today / Week / Month top bars. One save dialog picks the .xlsx; the CSVs go to a `<name> (CSV)` folder next to it. Rows belong to the day they start on (a session crossing midnight is listed once). Minutes have one decimal; `Actual` and `Overtime` come from the segments. Daily summary lists days up to today; Goal met is computed on every day, Score is blank on days off. Formula escaping applies to CSV only, because .xlsx cells are typed text and never run. | Claude (Phase 7) | Keeps every export sheet consistent with the reports and with the DB counts. | Separate dialogs for xlsx and the CSV folder |
| P42 | **Autostart and uninstall.** The `autostart` setting writes `HKCU\…\Run\Spyder` through `app.setLoginItemSettings`, at launch and whenever the setting changes, but only in the installed app, so dev and e2e runs never point the Run key at `electron.exe`. The uninstaller deletes the Run entry and keeps `%APPDATA%\Spyder` (the database). Test hooks stay behind `SPYDER_DEBUG=1`, also in the installed app, so the smoke e2e can run against it (`SPYDER_EXE=<path>`). | Claude (Phase 8) | A stale Run entry would point at a deleted exe; user data must survive a reinstall. | Ship a separate test build with debug hooks compiled in |
| P43 | **Bar widget style (default)**, added after the user compared our widget with a real Rize widget screenshot. A flat 468×34 strip with three metrics (session timer · productive today in purple · percent of day) and a ☰ menu segment. States show by colour only (timer red when overtime/distracted, blue when paused). No hover card and no bottom strip (user, after first look). ☰ opens the dashboard; clicking the timer opens the panel. Full and Compact stay as alternatives (extends P31); ⇄ cycles compact → full → bar. | User (Phase 8, widget redesign) | The user found the pill styles not what they had in mind; the bar matches Rize's real widget while keeping Spyder's session timer first. | Literal "time since last break" first metric; replacing Full and Compact |
| P44 | **Never tracked:** `spyder.exe`, `electron.exe` (dev runs of Spyder), and Windows shell overlays (`ScreenClippingHost`, `LockApp`, `SearchHost`, `StartMenuExperienceHost`, `ShellExperienceHost`). The tracker ends the previous app's row when one takes focus and records nothing; reports also skip rows already stored. | User (Phase 8 feedback) | They showed up in Apps & sites and are not the user's work. | Count Spyder as neutral |
| P45 | **Today is one calm column** (ADHD-friendly): a single hero number (productive vs goal), a quiet stats line, a distraction note only when needed, timeline, one category bar + top 5 apps (`Show all`), sessions collapsed. Full and Compact keep their panel. | User (grilled, 2026-11-22) | The user wanted a purely informational bar that's one click from the dashboard. | Controls in the tray or on the Today page; whole bar draggable; always first word |
